# 架构与验收

## 两个产品如何协作

```text
代码生成 AI + audit-ready Skill
         │
         ├── 项目源码
         └── .aicodeaudit/handoff.json + evidence/
                         │
                   本地只读索引
                         │
              Python AST / JS 启发式提取
                         │
       结构地图 / 文件关系 / 阅读路线 / 引用检查
                         │
              人工阅读、笔记、逐项核实
```

`audit/analyzer.py` 接受路径到文本的映射，生成结构化索引。目录扫描与浏览器导入复用同一分析器。快照摘要由排序后的文件路径及内容共同计算。

`audit/handoff.py` 调用生成端 Skill 内同一份校验器，减少生产端与消费端协议漂移。源码、作者声明与用户进度分开保存。

`audit/server.py` 提供本机 HTTP API、SQLite 持久化、报告导出和可选模型适配。SQLite 连接以事务上下文提交并显式关闭，兼容 Windows 文件锁行为。模型仅获得有边界的检索片段，不拥有工具执行接口。

`web/` 为无需构建的原生 HTML/CSS/JS。所有导入文本都经 HTML 转义后显示；接口请求验证本机 Host 和来源；静态资源采用固定白名单。

## 验收范围

后端测试覆盖不同项目的动态解析、Python 相对导入、JS 目录导入、别名未解析提示、语法错误、秘密文件排除、路径穿越、内容快照、引用过期、伪造通过记录缺证据、真实 HTTP 导入/阅读/搜索/笔记、跨源阻断、快照更新、模型适配及本地索引移除。

模型适配测试使用本机模拟接口验证上下文和响应处理；不是对某个外部商业模型的在线质量评估。示例项目的业务单元测试有真实输出并由交接包引用；未据此宣称 HTTP、浏览器、并发或真实认证通过。

## 手工检查路径

1. 启动后导入示例项目，核对文件数、模块关系与功能说明。
2. 点击功能的源码入口，核对定位行、依赖与符号。
3. 保存笔记并标记已读，刷新后检查持久化。
4. 修改导入项目中的源码并重新索引，核对指纹提示与进度复核。
5. 搜索函数，打开结果，导出报告。
6. 用窄窗口确认导航、源码阅读和弹窗可达。

自动化通过不等于视觉效果、完整调用关系、语义正确或用户验收通过。
